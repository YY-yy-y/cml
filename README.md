# 🎂 С днём рождения, мамочка — интерактивная инсталляция

Статический проект (HTML/CSS/JS) для GitHub Pages: **телевизор + телефон + AR-поиск фотографий на воздушном шаре**.

- **Телевизор** (`index.html`) — праздничная заставка, QR-код, режим «охоты» и финал.
- **Телефон** (`phone.html`) — сканирует камерой фотографии, наклеенные на шарик, и после каждой находки на ТВ появляется кусочек поздравления.

Всё состояние — только в памяти: перезагрузка страницы полностью сбрасывает прогресс.

---

## 1. Фотографии

Разложи файлы строго так:

```
photos/1.webp … photos/15.webp      — коллаж на заставке (1.webp — главная, крупная)
targets/ar1.webp … targets/ar5.webp — превью 5 «искомых» фото (для прогресс-бара на ТВ)
```

- Коллаж: 15 фотографий, `1.webp` — самая важная (в центре, крупная).
- `ar1.webp`–`ar5.webp` — это те 5 фотографий, которые будут наклеены на шарик и которые мама будет искать. **Порядок важен** и должен совпадать с порядком в файле целей (см. ниже).

> Все имена и пути настраиваются в [`js/config.js`](js/config.js).

---

## 2. Как получить `targets/targets.mind`

`targets.mind` — это скомпилированный файл целей для трекинга (5 целей, индексы 0–4).

1. Открой компилятор: **https://hiukim.github.io/mind-ar-js-doc/tools/compile**
2. Загрузи изображения `ar1.webp`, `ar2.webp`, `ar3.webp`, `ar4.webp`, `ar5.webp` **строго в этом порядке** (порядок задаёт индексы 0–4).
3. Нажми **Start**, дождись компиляции.
4. Скачай результат и положи его как `targets/targets.mind`.

**Советы для хорошего трекинга** (шарик изогнутый — трекинг капризный):

- Картинки должны быть **контрастными, с деталями** (текстуры, узоры, лица крупно), **не размытыми**.
- Избегай однотонных и симметричных изображений — по ним трекер «не цепляется».
- Наклеивай фото на шарик как можно ровнее, без сильных бликов.

> Тексты поздравлений в приложении **не привязаны** к конкретным фото — показывается следующий по порядку. Так что если перепутаешь порядок целей, поздравления всё равно выйдут в правильной последовательности.

## 3. Публикация на GitHub Pages

1. Создай репозиторий на GitHub и залей туда весь этот проект (со структурой папок).
2. В репозитории: **Settings → Pages**.
3. В разделе **Build and deployment**: Source = **Deploy from a branch**, Branch = **main**, папка = **/ (root)**. Save.
4. Через 1–2 минуты появится ссылка вида `https://<логин>.github.io/<репозиторий>/`.
5. Открой эту ссылку на **телевизоре** (это и есть `index.html`).

Камера и QR работают только по **HTTPS** — GitHub Pages это обеспечивает автоматически.

QR-код на ТВ ведёт на `phone.html` **того же деплоя** (URL вычисляется динамически) — ничего в коде для домена править не нужно.

## 4. Проверка через `?debug=1`

Добавь `?debug=1` к адресу — включится режим отладки, чтобы прогнать весь сценарий **без телефона**, прямо на ноутбуке.

**На ТВ** (`index.html?debug=1`):

| Клавиша | Действие |
|---|---|
| `1`–`5` | засчитать соответствующее фото |
| `0` | вызвать/скрыть QR |
| `9` | имитировать подключение телефона (режим охоты) |
| `R` | полный сброс |
| `F` | сразу финал |

В углу — панель со статусом связи и текущим состоянием.

**На телефоне** (`phone.html?debug=1`): после «Начать поиск» появятся кнопки-заглушки «Цель 1»…«Цель 5» — камера не нужна.

Без `?debug=1` вся отладка скрыта. Клавиши `1`–`5` на ТВ при этом остаются как **аварийный ручной ввод** — если связь отвалится посреди праздника, можно засчитать фото с пульта/клавиатуры вручную.

### Скрытый вызов QR на празднике (без отладки)

QR можно вызвать любым из способов (все незаметны гостям):

- нажать пультом `Enter` / `Space` / `→` / `0`;
- кликнуть в **невидимую зону в правом нижнем углу** экрана;
- сделать **тройной клик/тап** в любом месте за 1.5 секунды.

Повторный вызов или `Escape` — вернуться на заставку.

## 5. Чек-лист перед праздником ✅

- [ ] Телевизор открыт на ссылке деплоя и переведён в **полноэкранный режим** (`F11`).
- [ ] **Звук выключен** (страница без звука, но на всякий случай).
- [ ] **Телефон заряжен** (AR + камера + Wake Lock сажают батарею).
- [ ] **Интернет есть на обоих устройствах** (нужен для связи через PeerJS и загрузки библиотек с CDN).
- [ ] **Свет в комнате достаточный** для камеры — иначе трекинг фото на шарике будет нестабильным.
- [ ] Фото `ar1`–`ar5` **наклеены на шарик** ровно и без бликов.
- [ ] Проверил сценарий заранее через `?debug=1`.
- [ ] Вписал свои тексты поздравлений в [`js/config.js`](js/config.js) (поля помечены `// ЗАМЕНИТЬ`).

## Технологии

- **PeerJS** (публичный брокер) — связь ТВ ↔ телефон, без бэкенда.
- **MindAR** (image tracking, three.js) — распознавание фото камерой.
- **qrcode** — генерация QR на клиенте.
- Всё остальное — чистые HTML/CSS/JS, без сборки. Библиотеки подключаются с CDN.

## Структура

```
index.html          экран телевизора
phone.html          экран телефона (AR)
css/tv.css          стили ТВ
css/phone.css       стили телефона
js/config.js        ВСЕ настраиваемые данные
js/connection.js    связь ТВ ↔ телефон (PeerJS)
js/collage.js       коллаж на заставке
js/particles.js     фоновые частицы (пыльца, светлячки, лепестки)
js/tv.js            логика ТВ
js/phone.js         логика телефона + AR
photos/1..15.webp   фото коллажа
targets/ar1..5.webp превью найденных фото
targets/targets.mind скомпилированные цели MindAR
```
